# Native feel для Capacitor-приложения (только ветка `mobile`)

## Цель

Мобильное приложение (Capacitor) должно ощущаться нативным, а не как сайт: вкладки не должны каждый раз пересоздаваться и грузиться заново, элементы не должны «появляться после загрузки».

**Только ветка `mobile`.** Сайт (`front`) не трогаем: коммиты идут в `mobile`, обратно в `front` не мержим. Новая логика — в новых файлах, под `Capacitor.isNativePlatform()`, правки общих файлов (Layout, router) минимальные, чтобы слияния `front → mobile` не конфликтовали.

## План

1. **Keep-alive вкладок нижней панели** (`/`, `/favorites`, `/chats`, `/profile`) на React 19.2 `<Activity>`: монтируются при первом заходе и дальше только прячутся; пока вкладка скрыта, её эффекты (Mercure, поллинг) на паузе; скрытым вкладкам подставляется замороженный router-location; скролл сохраняется на каждую вкладку отдельно. Остальные маршруты (тикет, категория, создание, legal) рендерятся через Outlet как раньше.
2. **Stale-while-revalidate** для списков (чаты, избранное, мои тикеты, лента, профиль): мгновенный показ из сохранённого кэша и тихое обновление в фоне (тот же приём `persistKey` + `peek`, что уже сделан для категорий).
3. **Холодный старт**: `@capacitor/splash-screen` держится до первых данных (максимум ~2,5 с), скелетоны вместо полноэкранных спиннеров, когда есть кэш.
4. **Полировка**: без выделения текста вне полей ввода, `overscroll-behavior: none`, без подсветки тапа и hover-стилей на тач-экране, тактильный отклик (`@capacitor/haptics`), переходы между страницами, pull-to-refresh на списках.
5. **Навигация**: аппаратная кнопка «назад» Android (`@capacitor/app`), `@capacitor/keyboard`, предзагрузка вкладки при нажатии, `React.lazy` для не-табовых страниц (бандл ~1,2 МБ).
6. **Офлайн и устойчивость**: баннер офлайна (есть `NetworkContext`), повтор отправки неотправленных сообщений.

Каждый этап проверяется на эмуляторе (запись экрана + кадры) до выпуска сборки.
